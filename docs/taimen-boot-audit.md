# Pixel 1 hardware accesses in the kernel series, and what they do on taimen

Audit of 2026-10-22 (patches 0079-0183 as applied). Use it before enabling `rd=ufsroot0`.


**Bottom line:** if the next boot uses the current `tools/taimen/boot-xnu.sh` command line (`debug=0xc serial=3 cpus=1 keepsyms=1 -noprogress`, with no `rd=`), almost none of this code runs. Every Pixel 1 driver in bsd/dev starts from `sweet_ufs_init()`, and the only caller of that is `IOFindBSDRoot` when `rd=ufsroot0` (iokit/bsddev/IOKitBSDInit.cpp:773). On a boot without root, the only paths that run are the ADT-driven fbcon, the IOKit personalities, and backlight/blank, which userland triggers. As soon as you add `rd=ufsroot0`, the chain below runs on every boot. Its defaults are `sweetkeys=1`, `sweettouch=1`, `sweetusb=1` (read-only), `sweetperf=1` and `sweetclk=1`, so the PLL writes are on by default.

**Facts the table depends on:**
- **The taimen build compiles all of this code.** It passes `-DARM64_BOARD_CONFIG_SWEET -DARM64_BOARD_CONFIG_TAIMEN` (makedefs/MakeInc.def:69).
  - Gate with `ARM64_BOARD_CONFIG_TAIMEN`, which is a compiler flag and visible in every file.
  - Don't gate with `TAIMEN`: it only exists after `board_config.h` → `TAIMEN.h` is included, and the bsd/dev drivers don't include that directly.
- **Several Pixel 1 addresses land inside taimen's SPMI PMIC arbiter windows** (taimen /proc/iomem, hw/iomem.txt). A store there is an SPMI channel register access, not a no-op:
  - Inside `obsrvr 0x9400000-0xa3fffff`: 0x9820000 (RPM IPC), 0x99a2000 / 0x99d2000 (KRYO0/1), 0x99e0000 (MEMACC), 0x9a10000 (SAW), 0x9a11000 (CBF mux), 0x9a20000 (CBF PLL).
  - Inside `intr 0xa400000-0xa61ffff`: 0xa600000 (sweet DWC3).
  - Inside `chnls 0x8400000-0x93fffff`: 0x88e2000 (sweet QUSB2).
- **Every other Pixel 1 base has no claim in taimen's iomem:** 0x68000, 0x3xxxxx (GCC), 0x400a000/0x400f000/0x4400000/0x4c00000 (SPMI), 0x1010000+ (TLMM), 0x6400000/0x6480000, 0x066bf000, 0x004ab000, 0x7577000, 0x7af000, 0x8c0000, 0xb00000, 0xb40000, 0x90f00000.
  - On Qualcomm parts an access to an unclaimed address can return a bus abort or SError (a panic), or cause an XPU violation (a reset). So for these I write "unknown: may bus-abort", not "harmless".
- **`sweetkeys=0` cuts off all PMIC access.** It leaves `keys_core == 0`, so every `sweet_pmic_read`/`sweet_pmic_write` from battery, touch, perf and gpu returns false right away.
- **Not reached on any path:**
  - `sweet_spmi.c` (0xc440000) and `sweet_rpmh.c` (0x18220000) are compiled but nothing calls them.
  - `SweetCPU` matches `'qcom,kryo'`, but the taimen ADT says `qcom,kryo280` (mkadt.py:197), so it never matches. Its PSCI CPU_ON (0xC4000003) is standard anyway.
  - The taimen ADT has no `wlan` node.

### Gate these before the next boot that passes `rd=ufsroot0`
These write clocks, PLLs, regulators, PMIC, RPM or resets, or unknown registers:
1. **sweet_perf.c `perf_clocks` → `clk_pll_start(perf)`:** default-on PLL and mux writes to 0x6480000, and CBF writes inside the SPMI observer window. Also `clk_measure_mhz`, which writes GCC-debug and CBCR registers every 10 s. Boot-arg `sweetperf=0`.
2. **sweet_keys.c `keys_gpio_map`:** writes TLMM CFG = 3 to unknown 0x108e000 / 0x1089000. It also starts the whole wrong-arbiter SPMI scan that battery, touch, perf and gpu then use. Boot-arg `sweetkeys=0`.
3. **sweet_touch.c `touch_thread`:** GCC clock writes (0x352004, 0x31d008), TLMM and QUP writes, and RPM LDO votes through `sweet_rpm_ldoa`. Boot-arg `sweettouch=0`.
4. **SweetBattery `setupCharger` → `sweet_pmic_write`:** PMIC charger writes. Boot-args `sweetcharge=0 sweetbattery=0`.
5. **`sweet_fbcon_dcs`:** DSI0 command writes from userland brightness changes. Boot-arg `sweetbl=0`.
6. **sweet_usb.c:** read-only by default, but DWC3 and QUSB2 land in SPMI intr/chnls. Boot-arg `sweetusb=0`.
7. **Never pass on taimen yet:** `sweetgpu`, `sailfishwlan`, `sweetddr`, `sweetturbo`, `sweetboost`, `sweetfastboot`, `sweetresetfb`. The last two run even with `sweetperf=0`, and their IMEM / PS_HOLD constants are wrong for taimen (should be 0x146bf65c / 0x10ac000).

**Cheapest gating:**
- **For the first boot:** append `sweetkeys=0 sweettouch=0 sweetusb=0 sweetperf=0 sweetbattery=0 sweetcharge=0 sweetbl=0` to `cmdline` in tools/taimen/boot-xnu.sh.
- **More durable:** wrap the keys/touch/usb/perf/gpu/wlan calls at bsd/dev/sweet_ufs.c:663-668 in `#if !defined(ARM64_BOARD_CONFIG_TAIMEN)`, and either return early from `SweetBattery::start` under the same macro or key it on the ADT compatible `'google,sailfish'`.
