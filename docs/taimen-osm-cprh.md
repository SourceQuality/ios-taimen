## 1. Clock prerequisites (GCC and APCS)

RCG mechanics (`set_rate_hid`, LOCAL2:150-167, `rcg_update_config` LOCAL2:109-128): CFG = CMD + 4;
`CFG = (CFG & ~0x71F) | div_src_val` (DIV [4:0], SRC_SEL [10:8], LOCAL2:74-75); then `CMD |= BIT(0)` (UPDATE) and
poll until CMD bit 0 reads 0, 500 x 1 us (LOCAL2:46, 118-127). `div_src_val = FIXDIV(div) | src << 8`,
`FIXDIV(d) = 2d - 1` (GCC:47-57; same macro OSM:273-284). Branch enable (LOCAL2:811-842): `CBCR |= BIT(0)`, then
poll `CBCR[31:28]` until 0x0 (or 0x2), 500 x 1 us (LOCAL2:627-630, 635-680; `gcc_hmss_rbcpr_clk` sets no
`.halt_check`, so the HALT poll applies: the enum value 0 is assumed, see 8).

## 2. L2 SAW4 (SPM driver, `msm_spm_dev_probe`)

The L2 SAW nodes are `qcom,spm-v2`, one `reg`, no mode child nodes, no `q2s`/`hw-flush`/`slpreq` resources
(DTS 5005-5034). Probe flow (SPMDEV, `msm_spm_dev_probe`): read `qcom,saw2-ver-reg` (0xFD0) and map `reg[0]`;
`msm_spm_drv_reg_init` reads VERSION and picks the offset table (SPM:650-674): major = `ver[31:28]`, minor =
`ver[27:16]` (SPM:237-248); major 4 / minor 1 selects `msm_spm_reg_offsets_saw2_v4_1` (SPM:97-120, 140-146; any other
version is a `BUG_ON`). Then for every `qcom,saw2-*` key present, `msm_spm_drv_upd_reg_shadow` writes the DT value to
the hardware at once (SPM:676-683 -> `msm_spm_drv_flush_shadow`, SPM:151-160). `msm_spm_drv_init` (SPM:685-715) and
`msm_spm_drv_reinit(dev, false)` (SPM:636-648) only **read** (SAW_ID 0xC04, then a shadow reload). Nothing else is
written: `qcom,cpu-vctl-list` only builds the CPU mask, the vctl/phase/pfm ports are only used by later calls.

| 2.2 | gold-l2 | SAW_AVS_CTL (+0x904) | 0x17812904 | 0x01010031 | `qcom,saw2-avs-ctl` (DTS 5016) |

| 2.4 | silver-l2 | read VERSION | 0x17912FD0 | as 2.1 | DTS 5026 |
| 2.5 | silver-l2 | SAW_AVS_CTL | 0x17912904 | 0x01010031 | DTS 5031 |
| 2.6 | silver-l2 | SAW_AVS_LIMIT | 0x17912908 | 0x04200420 | DTS 5032 |

The writes follow the `spm_of_data[]` key order (cfg, avs-ctl, avs-hysteresis, avs-limit, ...; SPMDEV), so AVS_CTL
precedes AVS_LIMIT. The two L2 nodes presumably probe in DT order (gold-l2 first); the order between them does not matter for CPRh. The meaning of the AVS_CTL bits
and of a LIMIT whose two halves are equal is not in any source in hand (section 8). Readback of the rail through the
SAW: `PMIC_STS` +0xC18 (0x17812C18 gold, 0x17912C18 silver; SPM:103), masked 0x300FF by Linux (SPM:226-234).

Derived counts (exact Linux integer math):

- GCNT = ceil(19.2e6 x 1000 / 1e9) - 1 = ceil(19.2) - 1 = **19 = 0x13** (CPR:591-608).

  `[28:25]` = 0x08000000 (CPR:248-257, 1391-1401).
- CORNER init/floor steps = ceil((V - 360000) / 4000); quot delta = ceil((quot - base_quot) / 4) (CPR:1139-1149, 318).

(open loop), `SAW_ERROR_STEP_LIMIT` = 0x21, `MARGIN_TEMP_CORE_TIMERS` = 0x00840000, `CPRH_REG_CTL` = **0x080A00B5**,
`CPR_CTL` = 0x21F. `CPRH_REG_CTL[16:11]` INIT_MODE and `[31:29]` LAST_KNOWN_VOLTAGE_MARGIN are never written by Linux
(CPR:252-259). `CPR3_REG_IRQ_EN` and the CPR3 `HW_CLOSED_LOOP` (0x3000) / `PD_THROTTLE` registers are not written for
CPRh (CPR:1519-1557).

Open-loop choice. Linux's own CPRh "open-loop" mode is `MARGIN_ADJ_CTL` bit 4 = 0 with everything else unchanged and
the loop still enabled: that is exactly what its debugfs switch does at runtime (CPR:5702-5707, 5782-5785) and what
`cpr3_regulator_init_ctrl` writes without `qcom,cpr-hw-closed-loop` (CPR:1522-1526, 1592-1593). For the first
bring-up use bit 4 = 0 **and** bit 29 (`CPRH_CORNER_CPR_CL_DISABLE`, CPR:241) in every CORNER register (the "open-loop
value" column below). Data that only closed loop needs: GCNT, STEP_QUOT, THRESH, RO_MASK, TARGET_QUOT, the
quot-delta/RO fields of CORNER, `MARGIN_ADJ_CTL` bit 7 and [31:26], and the fused target quotients / RO selects /
quotient offsets / closed-loop adjustments behind them (KBSS:1589-1818). Aging plays no part on this phone (3.1).
Two implementation options:

- **A (recommended):** write steps 2-23 exactly as listed (the values are fixed for this phone and given here), with
  step 9 = 0 and the bit-29 corner values. Moving to Linux's closed loop later is then: clear bit 29 on corners
  0..n-1 (the two crossover corners keep it, they are `use_open_loop` in Linux, KBSS:1486, 1524; CPR:1174-1175), set
  `MARGIN_ADJ_CTL` bit 4.
- **B (minimal):** skip steps 2, 12, 13; keep `RO_MASK(0)` = 0xFFFF; CORNER = init | floor << 8 | bit 29 (RO 0, delta
  0). Steps 3-8 and 15-23 stay as listed. Nothing closed-loop is then configured.

Either way the voltage CPRh requests for a corner in open loop is `base + init_steps x 4 mV` (CTL base 90 x 4 mV =
360 mV, multiplier 4), i.e. the "open-loop mV" column.

### 3.3 Per-corner values (combo 19) and CORNER registers

How each number is made (Linux order, KBSS:1868-1966):

1. Fused open-loop per fuse corner = ref + sign-magnitude(6 bit) x 10 mV (KBSS:461-475, 526-527, 1067-1070;
   UTIL:252-261). Values from DMESG:266-269, 277-280 (silver 608/676/798/926, gold 646/646/798/1036 mV).
2. + `qcom,cpr-open-loop-voltage-fuse-adjustment` tuple for combo 19 (per-combo layout, offset 4 x 19 = 76;
   UTIL:311-360, 1436-1474): silver +40/+24/+12/+30 -> 648/700/810/956; gold +8/0/+12/+52 -> 654/646/810/1088.
3. Monotonic per fuse corner (KBSS:1087-1094): gold SVS 646 -> 654 (DMESG:281 shows this override).
4. fmax corners (`qcom,cpr-corner-fmax-map`; silver single tuple 8/11/18/22, gold per-speed-bin tuple 8/12/20/30,
   UTIL:762-801). Corners up to the first fmax take fuse corner 0's voltage; the rest are linear in frequency,
   `y2 - (x2-x)(y2-y1)/(x2-x1)` with integer division (KBSS:1104-1136, UTIL:275-286). Frequencies are
   `qcom,corner-frequencies` (silver 22 entries; gold per-speed-bin layout, bin 2 = entries 58..87; UTIL:386-435).
5. + per-corner `qcom,cpr-open-loop-voltage-adjustment` (per-speed-bin layout: silver offset 44, gold offset 58;
   silver -4 x8, -8 x3, -12 x5, -16 x2, -20, -24, -28 x2 mV; gold -4 x8, -8 x4, -12 x6, -16 x2, -20 x2, -24 x3, -28 x5),
   then **monotonic again** (each corner >= the previous one, `qcom,cpr-open-loop-voltage-min-diff` absent) (UTIL:1483-1549).
6. Round **up** to 4 mV, clamp to the DT floor/ceiling (`CPR3_ROUND` = DIV_ROUND_UP x step, CPRH:857; UTIL:1278-1295).
7. APM: for corners with floor < 800 <= ceiling: if open-loop >= 800, floor = 800 (hysteresis 0); else ceiling = 796
   (UTIL:2048-2094). MEM-ACC, same with 852 (floor = 852 or ceiling = 848) (UTIL:2114-2157).
8. Ceiling = open-loop (`qcom,cpr-scaled-open-loop-voltage-as-ceiling`, UTIL:1309-1320). This is what OSM reads back
   (`cpr3_regulator_list_corner_voltage` returns the ceiling, CPR:4309-4320).
9. Floor = max(floor, roundup(ceiling - `qcom,cpr-floor-to-ceiling-max-range`)) (32 mV, 40 mV for the top fuse
   corner), then floors made monotonic (UTIL:1334-1395).

## 4. Voltage table check against the plan (section 2 of `taimen-clocks-plan.md`)

The tables in 3.3 are the per-corner voltage tables (open-loop = ceiling, floor), one row per CPRh corner.
Comparison with the plan:

- **Silver:** all 15 corners the plan lists agree (644 ... 928 mV). The plan omits corners 1-7 (300-748.8 MHz), all
  644 mV.
- **Gold 902.4-1132.8 MHz (corners 9-12): Linux gives 652 mV, the plan says 648.** The per-corner adjustment (-8 mV)
  takes them to 646 mV, but `cpr3_adjust_open_loop_voltages` then forces each corner to at least the previous one
  (UTIL:1534-1543), i.e. corner 8's 650 mV, which rounds up to 652. Corner 1 (300 MHz) = 652 mV is confirmed by
  DMESG:327 ("300000000 Hz, 652000 uv" on cpu4).
- Gold corners 13-28 and 30 agree with the plan. The plan omits corners 1-8 (652 mV) and corner 29 (2342.4 MHz,
  1052 mV, used by LUT rows 31 and 32).
- The plan's "rail needed (+16 mV)" rows are not Linux behaviour: aging is disabled on this phone
  (`qcom,allow-aging-voltage-adjustment = <0>`), so Linux runs exactly the open-loop values as ceilings and closed
  loop only lowers from there. +16 mV is a margin of the plan's own.
- The plan's MEM-ACC remarks match: level 3 starts at silver 1747.2 MHz (VC 19) and gold 1881.6 MHz (VC 21), the first
  corners at or above 852 mV (5.7). The plan's short version says silver above 1555.2 and gold above 1728 need
  "MEM-ACC level 3": that holds only from 1747.2 / 1881.6; silver 1670.4 and gold 1804.8 need APM on APC but stay
  at level 2.

## 6. APM and MEM-ACC

- **Software writes nothing.** On v2 Linux never touches the APM (mode 0x179D0004 silver / 0x179D0010 gold, status
  0x179D000C / 0x179D0018) or MEM-ACC (0x179D1360/1364 silver, 0x179D1368/136C/1370 gold) registers. The code that
  programs them into the sequencer (`clk_osm_program_apm_regs`, the MEM-ACC cfg/value block) runs only with
  `secure_init` (OSM:1971-1999, 2020-2039, 2348-2369), which v2 refuses; DT values such as `qcom,apm-mode-ctl` and
  `qcom,*-apcs-mem-acc-cfg/-val` are parsed only on that path (OSM:1194-1233). The CPRh nodes have no `qcom,apm-ctrl`
  and CPRh never gets a mem-acc regulator (UTIL:1231-1237; KBSS never calls `cpr3_apm_init`/`cpr3_mem_acc_init`).
- **Who switches: the OSM sequencer** (TZ-loaded microcode), during the DCVS transition, using what TZ preloaded (the
  register addresses and mode values the secure-init path shows: APM MX mode 0, APC mode BIT(1), status mask 0x1F,
  MX status 0, APC status 3, OSM:146-150, 1971-1999) plus what Linux sends in 5.7-5.8 (thresholds, crossover VCs, the
  level-3 L value). While switching it parks the rail at the CPRh crossover corners: APM crossover VC 22/30 = 880 mV,
  MEM-ACC crossover VC 23/31 = 852 mV (3.3).
- **CPRh's part** is static: the crossover corners and the floor/ceiling clipping (3.3 step 7) so that no corner's
  range straddles 800 or 852 mV.
- Resulting switch points: silver APM on APC from VC 18 (1670.4 MHz), MEM-ACC level 2 from VC 11 (1094.4), level 3
  from VC 19 (1747.2). Gold APM on APC from VC 20 (1804.8), level 2 from VC 12 (1190.4), level 3 from VC 21 (1881.6).
- Expected readbacks: APM status `& 0x1F` = 0 (MX) below the APM VC, 3 (APC) at or above it. MEM-ACC: if the nine
  `qcom,perfcl-apcs-mem-acc-val` cells are level-major over the three cfg registers (an inference; the layout lives in
  the microcode), gold levels 1/2/3 read (0x1368, 0x136C, 0x1370) = (0, 0, 0x80000000) / (0, 0, 0) / (0, 0, 1); silver
  (0x1360, 0x1364) = (0, 0x80000000) / (0, 0) / (0, 1) (DTS 2492-2495).
- XNU must not write APM or MEM-ACC once the OSM is enabled, and must enter OSM control with them as XBL left them
  (route G1 does not change them).

"PLL already at L 90" -> row 19. Linux never does that (its first transition is to row 0), so the parked path is the

the safe fallback is 0x179C3F10 = 0 (row 0, GPLL0, 652 mV), then stop.

## 8. Open questions (with where I looked)

1. **Sources.** Everything cited is in `research/dl/msm-wahoo/` (not in git: downloaded GPL sources), `spm_devices.c` excepted (read online, so no line numbers). `cprh.py` there replays the Linux arithmetic that produced the 3.3 and 5.2 tables (arguments: live.dts, output .md).
2. **SAW4 AVS semantics.** `qcom,saw2-avs-ctl` 0x01010031 and `qcom,saw2-avs-limit` with equal halves
   (0x0470/0x0470 gold, 0x0420/0x0420 silver): no source in hand documents the v4.1 AVS fields in mV mode (SPM only
   has 8-bit `set_avs_limit`, SPM:296-308, and the 0x300FF `PMIC_STS` mask, SPM:226-234). Linux writes them and
   works; replicate verbatim.
3. **CPRh behaviour between loop enable and the first OSM request** (does it send a voltage at once?). Linux enables
   apc0 with silver at 1555.2 MHz from its PLL and silver survives (DMESG:274), which argues "no", but nothing in
   CPR/KBSS says so.
4. **CPRH_STATUS `[17:6]` units** (mV or steps): CPR:261-264 only names the field; Linux reads only `[5:0]`
   (CPR:4524-4534).
5. **Reset values of fields Linux leaves alone** (`CPRH_REG_CTL[16:11]`, `[31:29]`; the rest of `MARGIN_ADJ_CTL`,
   `SAW_ERROR_STEP_LIMIT`, `MARGIN_TEMP_CORE_TIMERS`). Do the same RMW; the "final" values in 3.2 assume zeros.
6. **Hand-over state the sequencer expects for the gold PLL.** Linux v2 never writes the PLL; in Linux the gold
   cluster is on GPLL0 at OSM enable and the gold PLL is as XBL left it (unknown here; the C0b dump in the plan would
   show it). Under route G1, XNU has the PLL running at L 90. Whether the microcode tolerates a running, XNU-programmed
   PLL (USER/CONFIG from silver's template) is unknown. Silver in Linux (PLL running at L 81 at OSM enable) suggests a
   running PLL is fine.
7. **MEM-ACC value layout** (level-major or register-major) and the meaning of the per-row SPARE vs the threshold VCs
   inside the microcode: only the secure-init writer shows the registers (OSM:2020-2039, `SEQ_REG(60+i)`), not the
   order. Used here only for readback expectations.
8. **Gold-only OSM.** Linux always programs and enables both clusters; whether the TZ microcode or TZ's io-write
   allow-list cares about order or completeness (silver rows 1-6, 13-17 skipped) is unknown.
9. **Autonomous OSM behaviour under XNU idle.** CC-based DCVS stays enabled (`SPM_CC_DCVS_DISABLE` = 0), PC override
   index 0, retention counted as active, WFx/PC droop FSMs on. With XNU's WFI-only idle the OSM may lower or boost
   the cluster on its own (core-count rows). Semantics are not in the sources.
10. **`lmh_lite_clk_src`** (the OSM clock RCG's source 1) is an anonymous ext clock (OSM:334); that it is the 300 MHz
    `hmss_gpll0` is inferred from 200 = 300 / 1.5.
11. **Branch halt-check default** for `gcc_hmss_rbcpr_clk`: no `.halt_check` (GCC:1727-1737); that 0 = HALT (poll
    `CBCR[31:28]`) needs `clock-local2.h`, not read.
12. **LMh**: OSM's probe ends with `of_platform_populate` (OSM:3423), which creates the `qcom,limits-dcvs@0/1`
    (`qcom,msm-hw-limits`) devices (DTS 2511-2520). That driver (`msm_lmh_dcvs.c`, not read) may write OSM or LMh
    registers or issue SCM calls; not needed for bring-up, but Linux has it.
13. **PMIC readback**: whether S13 `VOLTAGE_LSB/MSB` (0x3840/41) reflect a voltage the SAW sent (as opposed to the
    last software write) is unverified; `qpnp-regulator` reads them for its own set point only (QPNP:1146-1147).
    Cross-check with SAW `PMIC_STS` and CPRH_STATUS.
14. **LUT readability**: Linux only writes the LUT; reading `B+0x1150..` back is untested (plan section 4).
15. **`regulator_list_corner_voltage` constraints**: the regulator core (not read) could clip by
    `regulator-min/max-microvolt` (corner numbers 1..23 silver, 1..34 gold, DTS 4833-4834, 4905-4906); every LUT VC
    is inside those ranges, so it does not change any value here.
